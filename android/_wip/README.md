# android/_wip — SUPERSEDED, do not build on this

This directory is the abandoned first-generation Android relay idea, parked here
so the tree is not misleading. It is **not** the current approach and no code
should be built on top of it.

## Why it is superseded

1. **Direction change.** The plan was for the phone to act as a BLE *central* to
   both the Flipper (BLE serial peripheral) and the Even G2 glasses. That is no
   longer the goal: the Even **R1 ring is a BLE peripheral** and the glasses are
   BLE **centrals** that connect to it. The working shape now is for the Flipper
   to *impersonate the R1 ring*, so no Android app is needed at all.

2. **The protocol layer is FABRICATED.** `app/.../ble/EusPackets.kt` implements a
   made-up frame `[FLAGS][LEN_HI][LEN_LO][CMD][PAYLOAD][XOR-checksum]` with
   fictitious commands `0x20 SCROLL / 0x21 TAP / 0x22 LONG_TAP / 0x23 DOUBLE_TAP
   / 0x24 NAV_BACK / 0x25 NAV_HOME` (and `0x01 PING / 0x02 AUTH / 0x10/0x11/0x12`).
   **None of this is real.** The real G2 framing is `AA 21` magic, then
   seq/len/total/index/sid/flag, then payload, then a little-endian CRC-16.
   The authoritative, golden-tested implementation is `relay/g2proto.py`
   (mirrored from the vendored `vendor/even-g2-js/g2.js`). This Kotlin code was
   written against the same hallucination that once poisoned the Flipper app.

3. **Unfinished.** `ui/ControllerViewModel.startScan()` is a literal
   `// TODO: implement scan` stub, and `connect()` never actually connects.

## What is still valid here

Only the EUS *UUIDs* happen to be correct, and only because they match
`relay/g2proto.py`:
- service `00002760-08c2-11e1-9073-0e8ac72e5450`
- write/notify `...5401` / `...5402`
- also `...0000`, `...6450`, `...7450`

## If you ever revive an Android app

Do **not** reuse `EusPackets.kt`. Port the real protocol from `relay/g2proto.py`
(the names/semantics there are the contract) and prove it byte-for-byte on the
JVM against vectors generated by that Python module, before writing any BLE code.
